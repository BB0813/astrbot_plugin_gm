## 6. 经验教训

### 值得关注的要点

1. **复合 Issue 分类双轨**：当一个 Issue 包含 enhancement + command-removal 时，应分别评估而非统一用 enhancement

2. **owner-driven 信号利用**：
   - Issue 作者明确是仓库维护者时，删除类子诉求应主动降 low
   - 当前分析未利用仓库背景信息

3. **跨 Issue 互引强化**：#131 与 #139 功能相近，应显式互引而非仅参考

4. **权限不对称风险的精确表述**：当前描述"QQ 原生取消群待办通常需群主权限，与 Issue 所提'群管或群主'存在潜在冲突"——建议进一步说明"如果 API 不支持群管权限，则该 Issue 无法按描述实现，需调整为'仅群主可取消'"
