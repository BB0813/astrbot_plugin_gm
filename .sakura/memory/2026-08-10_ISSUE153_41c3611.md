## 6. 经验教训

### 6.1 命令删除类 Issue 审查要点

```
□ 七处同步检查清单是否完整
□ 依赖该命令的别名/快捷方式是否清理
□ 使用该命令的示例/教程是否需更新
□ 是否有使用统计（帮助评估影响范围）
```

### 6.2 breaking-change 评估修正

| 场景 | 评估 |
|------|------|
| 配置项删除 | 0.90-0.95 合理 |
| **命令删除** | 0.70-0.80 更合理 |
| 默认值变更 | 视影响范围 |

命令删除的 breaking-change 应低于配置项删除，因为：
- 用户可感知（会收到错误提示）
- 迁移路径明确（使用保留的命令）

### 6.3 可行性评估模板修正

```
【工作量估算】
- 代码变更：X 行（删除/修改）
- 文件同步：Y 处
- 文档更新：Z 处
- 测试需求：是否有/无
- 实际评估：[small/medium/large]
```

### 6.4 优先级与 breaking-change 一致性

**问题**：原分析将优先级设为 `low` 而 breaking-change 置信度 0.92，逻辑矛盾

**修正原则**：
- breaking-change ≥ 0.85 → 优先级至少 `medium`
- 低优先级仅适用于"无用户影响"或"纯文档更新"场景
