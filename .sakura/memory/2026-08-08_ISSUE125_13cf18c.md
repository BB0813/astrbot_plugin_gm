# Issue #125 分析反思

## 核心问题：分析结果完全失效

本 Issue 的原始内容非常清晰：**`/取消头衔` 命令执行后头衔仍存在**，疑似 bot 权限不足或目标用户为群主。这是一个典型的群管理 bug，涉及 `special_title` 清空语义与 OneBot 适配器兼容性。

然而分析结果将分类退化为 `other`、可行性写"无法评估"、建议标题为"无建议"、建议标签为空——**这是典型的"字段校验失败触发了整体降级"反模式**，严重违反了项目记忆中明确警示的规则。

## 1. 分类与优先级准确性

**分类严重错误**：结果为 `other`，但根据项目记忆：
> 明确运行时报错、命令参数类型错误、用户反馈"更新后仍存在"时，主分类应为 `bug`

本 Issue 正是用户反馈"清除后仍存在"的运行时报错，分类应为 **`bug`**。

**优先级判断基本合理**：`medium` 与原标题 `[bug][medium]` 一致，且符合项目记忆中"`medium` 适用于核心命令局部不可用、群管理命令提示成功但实际未生效"的定义。优先级无需调整。

---

## 2. 标签推荐质量

**建议标签为空**——这是最严重的反模式之一。项目记忆明确指出：
> 标签在不确定体系时也应给通用候选并注明需映射，**不能留空**

按项目记忆的"头衔 bug 至少给 `bug`、`command`、`group-management`、`title/special-title`、`onebot/compatibility`"模板，本 Issue 应推荐：

- `bug`（根因分类）
- `command`（命令执行层）
- `group-management`（群管理模块）
- `title` / `special-title`（头衔专项）
- `onebot` / `compatibility`（适配器兼容）
- `needs-info`（需补充 bot 角色、目标用户身份、OneBot 实现版本等关键排查信息）

`good first issue` 置信度应 ≤0.15：头衔清空涉及多适配器语义差异、权限链路排查，不适合新手。

## 3. 可行性判断质量

**"无法评估"是错误降级**。根据项目记忆：
> 可行性在信息不足时也应有条件判断，不能写"无法评估"

即使缺乏完整执行日志，根据现有信息可以给出有条件的可行性判断：

- **修复方向明确**：`/取消头衔` 应在调用 `set_group_special_title` 后用 `get_group_member_info` 回读确认，并处理 `special_title=""` vs `" "` 的语义差异
- **工作量预估**：低-中，主要是增加回读校验 + 处理空白头衔兜底 + 增加权限/角色前置检查
- **风险点**：需区分 bot 角色（管理员/群主/普通成员）、目标用户是否群主（群主头衔不可由管理员修改）、不同 OneBot 适配器对空标题的处理差异

应给出类似"低-中工作量，需补充 bot 角色与 OneBot 实现版本信息"的条件性判断，而非"无法评估"。

## 经验教训

### 关键反模式再次触发

本次分析再次踩中了项目记忆第 1 条警示的核心反模式：
> **结构化输出校验失败 ≠ 信息不足**：字段校验错误时应**仅修复字段输出**，不得把所有判断都退化为"无法评估"/`other`/空标签/无建议

`expected <REASON>` 是字段输出层的校验错误，**不影响**分类、优先级、可行性、标签、标题等实质性判断。本应在原分析基础上局部修复输出格式，而非整体降级。

### 头衔类 Issue 的标准化分析路径

基于项目记忆的"头衔类 bug 排查模板"，未来遇到 `/取消头衔`、`/设头衔` 类 Issue 应直接套用：

1. **必查项**：bot 角色、目标用户身份（是否群主）、OneBot 实现版本、AstrBot/插件版本与 commit、完整执行日志、最近配置变更
2. **API 语义**：`set_group_special_title` vs `set_group_card` 的区分；`special_title=""` vs `" "` vs 空白字符的语义差异；`duration` 参数语义
3. **回读验证**：是否调用 `get_group_member_info` 回读确认，避免"返回成功但实际未生效"
4. **必要追问**：补充上述排查信息后才能确定修复方向

### 校验失败的 Pre-check 规则

在本次反思中确认：在任何字段出现"无建议/无法评估/空"前，必须先确认这是否源于校验失败而非真正的判断缺失。若为校验失败，应**局部修复**而非**整体降级**。这是必须固化的操作纪律。
