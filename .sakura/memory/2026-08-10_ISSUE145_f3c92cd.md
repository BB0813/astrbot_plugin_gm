## 6. 经验教训

### 本次分析的核心失误

| 失误 | 严重程度 | 根因 |
|------|----------|------|
| 缺少 `privacy` 标签 | **P0** | 未对"删除用户数据"进行隐私合规识别 |
| 可行性分支与验证约束矛盾 | **P1** | 未意识到"未验证外部仓库则工作量不可信" |
| 默认值决策路径未显式 | **P1** | 遗漏 #142 第 5 条决策路径 |
| 通知风暴/throttling 缺失 | **P2** | 未对照 #143 经验清单 |
| 措辞"未检测到重复" | **P0** | 违反强制模板（已第 N+1 次触犯） |

### 动作联动型 Issue 必检清单（本次漏项）

```
1. ✅ 事件钩子识别（group_decrease）
2. ✅ 副作用边界（踢人→清记录）
3. ❌ 隐私合规（缺失！涉及删除他人数据）
4. ❌ 通知风暴防护（批量撤回触发）
5. ❌ 速率限制（throttling 缺失）
6. ✅ 跨适配器兼容性（compatibility 标签）
7. ✅ 配置按群覆盖（group_overrides）
8. ❌ 默认值决策（未显式）
9. ❌ 外部仓库验证（标注但未执行）
10. ✅ 回执一致性（"成功 N / 跳过 X / 失败 Y"）
```

1. **隐私标签强制检查**：涉及用户数据删除/修改时，自动提示添加 `privacy` 标签
2. **"必须先访问外部仓库"与可行性分支互斥**：若标注此约束，则可行性分支改为"待验证后确定"
3. **动作联动型模板强化**：将 #143 必检清单内化为 P0 前置检查
