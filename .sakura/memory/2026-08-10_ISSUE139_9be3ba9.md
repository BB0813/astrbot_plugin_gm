## 六、经验教训

### 1. 双向复合 Issue 标签必须拆分

| 方向 | 标签 | 置信度 |
|------|------|--------|
| 删除侧 | `command-removal` | 0.90 |
| 删除侧 | `breaking-change` | 0.90-0.95 |
| 删除侧 | `enhancement` | 0.95 |
| 新增侧 | `group-todo` (新建) | 0.85 |
| 新增侧 | `breaking-change?` | ≤0.30 |
| 新增侧 | `onebot-extension` | 0.55-0.65 |

### 2. `onebot` vs `onebot-extension` 区分（高优先级）

- **标准 v11 API** → `onebot` (≥0.55)
- **QQ 私有扩展 / 非标准 API** → `onebot-extension` (0.55-0.65)
- 群待办类 API 必须用 `onebot-extension`

### 3. 权限不对称风险必须显式映射到优先级

- QQ 原生"撤销群待办需群主"vs Issue 描述"群管或群主"→ 权限不对称
- 这是 `needs-discussion` (≥0.75-0.85) 的硬支撑，不是降 low 理由
- owner-driven 纯减法降 low 应基于"主动决策 + 无横切"，而非"风险存在"

### 4. `needs-info` / `needs-discussion` 双校准硬约束

- owner-driven 缺决策 → **同时给** `needs-info` (≤0.30) + `needs-discussion` (≥0.75-0.85)
- 权限不对称风险 → 仅 `needs-discussion` (≥0.75-0.85)

- [x] 双向诉求显式拆分（删除侧 vs 新增侧）
- [x] breaking-change 分别评估（0.90-0.95 vs ≤0.30）
