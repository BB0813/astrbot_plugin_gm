建议更新规范：

## 四、经验教训

### 4.1 审查失败的处理

| 场景 | 当前状态 | 建议改进 |
|------|---------|---------|
| 工具输出验证失败 | 产生 None/10 评分 | 应拒绝提交，标记为"审查失败" |
| 增量包含大量配置变更 | quick 策略仍使用 | 提示风险升级审查策略 |

### 4.2 增量审查的特殊风险

**13 个提交的增量审查难点：**
- `d566ed69` 彻底移除 plugin_admins —— 需验证命令移除七处同步
- `8b01aa61` Merge PR#149 —— 需确认合并前审查
- 多个 `chore(sakura)` 提交 —— 需确认不引入功能变更

**Quick 模式下无法验证：**
- 配置项移除是否遗留文档引用
- 合并提交是否带入了未审查代码

### 4.3 配置项变更审查清单

```
□ 新配置项默认值是否安全？（false 优于 true）
□ 枚举值是否有边界校验？
□ 数值范围是否在 schema 中限定（1-50）？
□ 配置项文档是否与代码注释一致？
```
