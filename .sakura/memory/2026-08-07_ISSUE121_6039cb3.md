## 3. 可行性判断质量

### 当前问题

当前可行性写成：

> 无法评估

这不理想。虽然没有读取代码，但从仓库背景和功能描述已经可以做有条件评估。

### 更合理的可行性结论

建议改为：

> 可行，但需要设计审批状态、权限校验、私聊/群聊消息路由和解禁动作，完整实现复杂度为中等。

### 技术依赖与风险

该功能不是简单加一个命令，关键点包括：

#### 1. 私聊事件没有群上下文

用户私聊 bot 时通常没有 `group_id`，因此必须要求用户提供群号，例如：

```text
申请解禁 123456789 我是误触发禁言
```

还需要校验：

- 用户是否确实在目标群；
- 用户是否确实处于群禁言状态；
- 如果是插件内部“禁我”状态，需要确认对应状态存储在哪里；
- 群禁言和“禁我”不能混为一谈。

#### 2. 审批必须有唯一申请 ID

不能只靠管理员回复“同意”或“驳回”。

否则会出现问题：

- 多个用户同时申请时无法区分；
- 多个群同时申请时无法区分；
- 管理员回复上下文丢失；
- 重复审批无法幂等处理。

更稳妥的设计是：

```text
同意 #123
驳回 #123 原因
```

或使用专用命令：

```text
/解禁审批 同意 123
/解禁审批 驳回 123 原因
```

#### 3. 权限校验必须严格

审批者必须是：

- 插件管理员；
- 或配置的审批管理员；
- 或目标群中有权限的管理员/群主，取决于项目设计。

如果在管理群审批，仍然要校验发言者 QQ，而不能只因为消息来自管理群就信任。

#### 4. 需要持久化或至少临时状态管理

应考虑：

- 申请 ID；
- 申请人 QQ；
- 目标群号；
- 申请原因；
- 申请时间；
- 当前状态：pending / approved / rejected / expired；
- 审批人 QQ；
- 审批时间；
- 驳回原因。

如果不持久化，bot 重启后申请会丢失。最小实现可以先内存保存，但需要明确限制。

#### 5. 调用解禁 API 的风险

同意后 bot 需要执行解禁动作，可能失败：

- bot 不在群；
- bot 不是管理员；
- bot 权限低于目标用户；
- 用户已经退群；
- 用户已经被其他管理员解禁；
- OneBot 适配器返回成功但实际未生效；
- 插件内部“禁我”和群禁言解除方式不同。

因此同意审批后不能只提示成功，最好要处理 API 异常和结果反馈。

#### 6. 配置、帮助和文档同步

新增功能应同步：

- `_conf_schema.json`
- 默认配置
- README
- 帮助命令
- 管理员配置说明

建议配置项包括：

- 是否启用解禁申请；
- 审批管理员 QQ 列表；
- 审批管理群；
- 申请有效期；
- 是否允许重复申请；
- 是否在群内通知用户；
- 是否允许处理“禁我”状态；
- 是否允许处理群禁言状态。

### 工作量估算

更合理的估算：

- 最小可用版：中等偏低；
- 可持久化、支持并发和过期的完整审批流：中等到中高。

## 6. 经验教训

### 1. 上游分析失败不能导致全字段空白

本次最大问题是错误信息被直接写进摘要，导致分析结果变成：

- 分类 `other`
- 标签空
- 可行性无法评估
- 标题无建议

这是流程问题。即使模型调用失败，也应根据 Issue 标题和摘要做基础判断。

应避免把“AI 分析失败”当作 Issue 摘要。

### 2. 审批流类需求应默认标记为 enhancement

“新增申请、审批、通知、自动执行”属于典型 workflow enhancement，不应归为 other。

尤其在群管理插件中，禁言、解禁、审批、管理员配置都属于核心群管理增强。

### 3. 私聊触发群管理动作时必须关注 group_id 缺失

这是该类需求的关键技术点。

用户私聊 bot 时，bot 不知道用户要申请哪个群，因此必须要求提供群号，或者维护此前禁言记录。

分析时应明确指出：

- 群号必填；
- 需校验用户是否在该群；
- 需校验禁言状态或“禁我”状态；
- 不能盲目对任意群执行解禁。

### 4. “同意/驳回”不能只靠关键词

管理员回复“同意”或“驳回”的设计过于模糊。

未来分析类似需求时，应主动建议：

- 申请 ID；
- 引用消息审批；
- 专用审批命令；
- 并发处理；
- 重复审批幂等；
- 申请过期机制。

### 5. 群禁言和插件内部“禁我”要分清

Issue 同时提到：

- 管理禁言；
- 禁我被禁言。

这可能对应两套机制：

- OneBot 群禁言；
- 插件内部对用户的屏蔽/禁用状态。

分析时不能默认二者都能用同一个解禁接口处理。

### 6. 自动解禁是敏感动作

需要强调权限边界：

- 只有配置的插件管理员或授权群管理员可审批；
- 管理群消息来源不等于审批者可信；
- 审批操作要记录日志；
- 解禁失败要反馈原因；
- 申请内容可能包含隐私，只能转发到可信管理员或管理群。
