# 反思报告：#143 踢人时清除聊天记录 + 合入外部仓库

## 1. 分类与优先级准确性

**分类 `other` 严重错误**。从项目记忆反模式章节可知："**校验失败短路器**"已被点名第 9-10 次触发，**结构化输出校验失败 ≠ 信息不足**，应仅修复字段输出，**不得把所有判断退化为"无法评估"/`other`/空标签/无建议**。

本 Issue 实际包含**三个可独立分类的子诉求**：

1. **合入外部仓库**（`ast/plugin_group_guardian`）→ `merge-request` + `external-repo`（项目记忆"合入外部仓库类"章节明确覆盖）
2. **功能需求：踢人时清除该用户聊天记录** → `enhancement`（权限模型调整 + 新增行为耦合）
3. **三档配置粒度**：全局配置 + 按群覆盖 + 指令触发 → 涉及配置 schema 重构

**优先级 `medium` 合理**——但需注意这是 `enhancement` 不是 `bug`。项目记忆"分类、优先级"章节："权限/配置粒度调整→ `enhancement`"。

**实际应升 medium 的核心理由**：
- 横切"踢人"这一高风险命令，增加副作用链路（"踢人后清理"链路 ≠ "撤回"链路，需分析是否引入"踢人失败但部分清理"的中间态 bug）
- 跨适配器差异：`delete_msg`/`get_group_msg_history` 跨 OneBot v11/v12/AstrBot 适配器差异显著
- 合入外部代码本身是**风险源**（项目记忆"合入外部仓库类"明确要求评估代码质量、依赖兼容、许可证、维护责任）

## 4. 可行性判断质量

**"无法评估"是退路式输出**。即使未读取外部仓库代码，仅基于需求描述本身即可给出分支估算：

**必含决策点（≥4）**：
- **D1 清理时机**：`kick` 调用前清理 / after `kick` 返回成功 / after `kick` + 状态回读后 / 异步队列
- **D2 清理语义**：踢人者本人消息仅 / 全员含踢人者 / 区分本人 vs 其他人 / 时间窗口（近 N 条 vs 全量）
- **D3 配置 schema**：是否引入 `clear_chat_history_on_kick` 三态（`off`/`kick_only`/`kick_and_command`）+ `clear_scope`（`all`/`self_only`）+ 按群覆盖键名
- **D4 跨适配器**：`get_group_msg_history` 走哪条路径（仓库记忆的"撤回缓存三层链路"：`recent_messages` → `message_history` → `get_group_msg_history` 兜底，本场景**反向**——要从历史中筛出该用户消息 ID）
- **D5 失败处理**：踢人成功但清理失败 → 是否回滚踢人 / 提示 / 静默
- **D6 指令触发**：独立指令 `/clear_user_history @user` vs 踢人时参数 `with_history`
- **D7 合入外部仓库的工作量**：阅读代码 + 接口对照 + 移植适配 + license 审查 + 测试

**可行性分支**：
- **A 最小**：仅复用外部 `group_guardian` 已有命令直接合入 → 20-40 行/0.5-1 天（**最可能与 owner 意图一致**）
- **B 标准**：合入 + 适配当前插件架构（配置 schema + 帮助同步 + metadata）→ 80-150 行/1-2 天
- **C 完整**：B + 跨适配器回读 + 按群覆盖 + 三档配置粒度 → 200-350 行/3-5 天
- **D 分阶段**：先 A（合入最小可用）→ 再 B（适配）→ 再 C（完整覆盖），共 4-7 天

**估算依据**：
- 仓库记忆：#131 群待办工作量 80-150 行/1-2 天作为基线
- 合入类工作量 = 阅读（外部代码量 × 0.3）+ 移植（接口对齐 × 0.5）+ 测试/文档（30%）

**应检索关键词**：`kick`、`踢人`、`清除聊天`、`clear`、`history`、`purge`、`群管理增强`。

**关联性提示**：

- #131 群待办——同样是"针对某用户批量操作"模式，可参考其指令格式与权限设计

3. **必给标签全部缺失**：未对照"合入外部仓库类"模板逐项勾选

### Issue 类型识别遗漏

**"合入外部仓库 + 借鉴功能"复合类型**在仓库记忆中已有专门章节覆盖，本应第一步触发模板对照。识别信号：

- 出现"按照 X 的代码实现"→ 触发借鉴+合入混合模式
- 出现"插件配置设置 / 按群覆盖 / 指令触发"三件套 → 触发配置粒度增强模式

### 仓库特有的"踢人副作用"风险

仓库记忆虽未沉淀"踢人副作用"模板，但 #130/#132 权限模型重构已多次涉及踢人。本 Issue 应作为**该模式第 1 次正式触发**被沉淀：

- 踢人是高风险命令（误踢=不可恢复）
- 增加副作用（清理聊天）= 失败态组合增多（踢成功清失败 / 踢失败清成功 / 部分清失败）
- 跨适配器 `delete_msg`/`get_group_msg_history` 差异显著
- 必须显式评估"清理失败是否回滚踢人"

### "借鉴外部仓库"的工作量建模

项目记忆"合入外部仓库类"章节已沉淀工作流（代码质量、依赖、许可证、维护责任、配置扩展、bot 权限），但**未沉淀工作量估算模型**。本 Issue 应补充：合入类 = 0.3×外部阅读 + 0.5×接口移植 + 0.2×测试文档，作为未来类似 Issue 的基线。
