# 项目概述：mjy1113451/astrbot_plugin_gm

> 累计反思 11 次

## 1. 项目简介

`astrbot_plugin_gm` 是一个用于 AstrBot 的 QQ 群管理插件，面向 QQ 群聊管理场景，提供插件管理员管理、禁言/解禁、自怼、踢人、撤回消息、设置群昵称、设置/取消专属头衔、设置/取消群管理员、设置精华消息等能力。

## 2. 技术栈与结构

- **主要语言**：Python 3.10+
- **插件框架**：AstrBot 插件体系
- **QQ 平台接口**：aiocqhttp / OneBot 相关 API
- **配置方式**：`_conf_schema.json` 定义配置项，`main.py` 读取并执行
- **许可证**：MIT License

```text
astrbot_plugin_gm/
├── main.py              # 插件主逻辑：命令、权限判断、配置读取、API 兼容
├── metadata.yaml        # AstrBot 插件元信息
├── _conf_schema.json    # 配置 Schema
├── README.md            # 安装、配置、命令和权限说明
├── docs/                # 补充文档
└── .sakura/             # 项目记忆、规则与反思
```

主要命令包括 `/设管`、`/取管`、`/禁言`、`/解禁`、`/禁我`、`/踢`、`/头衔`、`/取消头衔`、`/设管理`、`/取消管理`、`/设精`、`/设群昵称`、`/改昵称`、`/撤回` 等。

## 3. 权限与配置模型

项目采用多层权限设计：

1. **插件管理员**：由 `plugin_admins` 配置或 `/设管` 动态维护；群主默认具备插件管理员身份。
2. **QQ 官方群权限**：禁言、踢人、撤回、设置管理员、设置精华、头衔等操作还依赖机器人在 QQ 群中的官方权限和目标成员身份层级。
3. **专项权限与按群覆盖**：反思中多次提到 `title_admins`、`group_admin_admins`、`kick_admins`、`group_admins`、`group_overrides`、`get_group_setting` 以及 `has_title_admin_rights`、`has_kick_admin_rights`、`has_group_admin_rights` 等机制。后续权限需求应优先检查这些入口，避免只改命令层而遗漏权限判断函数。
4. **全局默认与群级覆盖**：多群场景必须明确缺省回退、空列表/空对象/`0` 值语义。缺失字段通常回退全局；显式空列表可能表示覆盖为无授权；`mute_kick_threshold=0` 这类值应能表示关闭功能，不能被误当作未配置。

常见配置项：

- `show_recall_notice`：撤回后是否发送提示
- `reject_re_add`：踢人后是否拒绝重新加群
- `plugin_admins`：插件管理员 QQ 列表，建议按字符串处理
- `group_overrides`：按群覆盖配置的重要入口，涉及专项权限和阈值类配置

## 4. 近期反思沉淀

### 4.1 AstrBot 命令参数解析

Issue #106/#110 等反复暴露命令参数注解风险：

- 若命令函数签名使用 `count: int = 0/1`，AstrBot 可能在进入函数体前做类型转换并报错，函数内 `try/except int(count)` 无法捕获。
- 复杂命令入口应尽量用 `str` 或原始事件接收，再在函数内部统一解析、校验并给友好提示。
- 同类问题要全局排查，不要只修一个入口；重点检查 `recall_cmd`、`recall_user_cmd` 及所有命令参数中的 `: int =`、`count: int`。
- 需要先判断错误发生阶段：插件启动、命令注册、命令调用前解析，还是函数体内特定输入触发。

测试应覆盖无参、正常数字、非法字符串、空字符串、负数、过大数字、中文数字、引用消息、带 @ 用户和数量等场景。

### 4.2 `/撤回` 命令语义与解析

Issue #109/#110 集中在撤回命令：

- `/撤回 1` 的用户直觉是撤回当前指令上方一条消息，而不是撤回指令本身。实现应优先获取群历史、过滤当前 `event.message_id`，再选择命令之前的 N 条可撤回消息。
- `count=1` 是最小复现用例，必须专门测试；同时测试 `/撤回 2/3`，避免只修单条。
- 历史消息接口风险包括：OneBot 实现不支持 `get_group_msg_history`、返回顺序差异、字段结构差异、当前命令是否出现在历史中、消息 ID 类型差异、撤回超时或权限不足。
- 历史接口不可用时应明确提示，不应回退为撤回指令自身并误报成功。
- `/撤回 @用户 N` 与 `/撤回用户 @用户 N` 存在入口语义重叠。若作为别名支持，必须复用同一权限校验、数量限制、群聊校验和失败提示。
- `@用户` 不应简单按空格切分；昵称可能包含空格，应优先依赖消息 segment、user_id 或 AstrBot/OneBot 提供的 At 结构。

### 4.3 取消头衔：API 成功不等于业务生效

Issue #111 表明 `/取消头衔` 可能出现“机器人提示成功但实际未清空头衔”：

- 关键链路：`unset_group_title_cmd` → `_clear_group_title` → `set_group_special_title` → `special_title=""`、`duration=-1`。
- 不同 OneBot 实现（如 NapCat/Lagrange/go-cqhttp）对空字符串、`duration=-1`、`duration=0`、不传 `duration` 的语义可能不同。
- 群管理类操作不能只看 action 返回 ok 就提示成功；应考虑回读 `get_group_member_info` 验证 `special_title`，或使用更谨慎的“已发送请求，请稍后确认”提示。
- 回读也可能受缓存和刷新延迟影响，必要时考虑短延迟、字段兼容和不确定提示。
- 还必须排查机器人是否有群主/管理员权限、目标用户身份是否高于机器人、QQ 官方限制或适配器吞掉权限错误。

处理“返回成功但未生效”类问题时固定检查链路：

```text
命令解析 → 权限判断 → API 参数 → 适配器兼容 → API 返回值 → 状态回读 → 用户提示
```

### 4.4 按群配置与配置 Schema/UI

Issue #107/#105 说明本仓库按群配置问题常分三层：

1. 业务逻辑是否按群读取；
2. 配置数据结构是否支持按群覆盖；
3. `_conf_schema.json` / 配置 UI / README 是否让用户能发现和设置。

例如 `mute_kick_threshold` 可能已在 `_record_mute_and_maybe_kick` 中通过 `get_group_setting(group_id, "mute_kick_threshold", 0)` 读取，但 `_conf_schema.json` 仍只把它展示为顶层全局配置，导致用户误以为不能按群设置。

修改配置时应同步：

- `_conf_schema.json`
- README 配置说明与示例
- 命令帮助/状态展示
- 兼容旧全局配置作为 fallback
- 明确 `group_overrides[群号][key]` 的缺失、空值和显式 `0` 语义

专项权限增强应优先复用 `group_overrides` 和 `get_group_setting`，同时避免旧 `group_admins` 等配置语义突然失效；如需改变，应提供兼容读取、迁移或废弃期。

### 4.5 Issue 分析与标签经验

- 标题为“。”、“，”或信息极少时，不能依赖标题分类、查重或标题保留，应从正文、错误提示和代码关键词重建问题。
- 结构化输出某字段校验失败（如 milestone/标题格式）不应导致分类、标签、可行性等有效判断整体丢失。
- 对 `[bug][medium]`、`[enhancement][medium]` 标题可作为高置信度信号，但仍要结合正文和代码验证。
- “版本已更新，问题还存在”不一定等于回归；只有确认旧版本正常、新版本异常时才标 `regression`。
- 重复检测要区分“同命令”与“同问题”：同属 `/撤回` 不代表重复，需比较症状、触发路径和修复点。
- 未掌握历史 Issue 或搜索证据时，应写“暂未发现重复”，并列出关键词，而不是绝对断言。
- 标签建议优先匹配仓库实际标签；未知时给通用主标签，并列出候选：`bug`、`command`、`group-management`、`configuration`、`schema`、`compatibility`、`documentation`、`usability`、`needs-info` 等。

## 5. 开发约定与注意事项

- 插件逻辑集中在 `main.py`，修改时应全局搜索相似命令模式，避免复制粘贴式遗漏。
- 改配置必须同步 `_conf_schema.json`、README 和必要的帮助文本。
- 权限类改动必须覆盖：全局配置、按群配置、命令入口、权限判断函数、文档说明和回归测试。
- 群管理操作依赖平台 API、机器人官方权限、目标成员身份和消息时效，必须处理接口失败、权限不足、适配器不支持和异常返回。
- 对 OneBot/AstrBot 兼容问题，应优先确认框架版本、插件版本/commit、适配器实现、完整堆栈和最小复现命令。
- 自动踢人、撤回、设管理、头衔等敏感操作要特别防止误报成功、误操作和越权授权。
