# 项目概述：mjy1113451/astrbot_plugin_gm

> 累计反思 88 次

## 1. 项目简介

`astrbot_plugin_gm` 是 AstrBot 的 QQ 群管理插件，提供插件管理员维护、禁言/解禁、踢人、撤回消息、群昵称、头衔、精华消息、官方群管理员设置等能力。逻辑集中在 `main.py`，依赖 AstrBot 插件体系与 aiocqhttp / OneBot API。

主要命令：`/设管`、`/取管`、`/禁言`、`/解禁`、`/禁我`、`/踢`、`/头衔`、`/取消头衔`、`/设管理`、`/取消管理`、`/设精`、`/取消设精`、`/设群昵称`、`/改昵称`、`/撤回`、`/撤回用户`、`/撤回自身`、`/消息列表`、`/发群公告`、`/删群公告`、`/添加群待办`（#131 待实施）、`/改群头像`、`/宵禁`、`/解除宵禁`、`/排名`、`/清除数据`、`/举报`。

## 2. 技术栈与结构

- **语言**：Python 3.10+；**框架**：AstrBot 插件体系；**接口**：aiocqhttp / OneBot action；**配置**：`_conf_schema.json` + 运行时读取；**许可证**：MIT。
- 主目录：`main.py`（命令、权限、配置、OneBot 兼容，2800+ 行）、`metadata.yaml`、`_conf_schema.json`、`README.md`、`docs/`。

## 3. 权限与配置模型

1. **插件管理员**：`plugin_admins` 或 `/设管` 动态维护；群主天然具备。
2. **QQ 官方权限**：禁言、踢人、撤回、设精、设/取消管理/头衔仍依赖机器人群内官方权限。
3. **专项权限/按群覆盖**：`title_admins`、`group_admin_admins`、`kick_admins`、`group_admins`、`group_overrides`、`get_group_setting` 及 `has_*_admin_rights` 机制。
4. **群待办权限特殊性**：QQ 群待办设置/撤销通常**仅群主可操作**（与既有 `_is_group_admin_or_owner` 不同），新增群待办相关命令时必须评估权限对称性。
5. **全局默认 + 群级覆盖**：明确缺省回退、空列表/空对象/`0` 的语义，`0` 可作关闭阈值不能误当缺失。
6. **跨私聊审批**：若新增私信申请解禁等远程审批功能，需明确管理员跨群代为操作的审计边界。

## 5. Issue 分析核心规则（高层摘要）

- **校验失败短路器（强制 Pre-check）**：任何字段出现"无/无法/空/未检测到"前必须确认是否源于校验失败；校验失败应**局部修复字段输出格式**，**不得整体退化为不可评估**——实质性判断（分类/可行性/标签/关键问题列表）维持原始判断。
- **重复检测措辞**：见 §4.29 禁用清单 + 强制措辞模板。
- **必给标签逐项核对**：涉及 OneBot 扩展 API、引用消息触发、写类对称命令等场景，必须对照相关模板（#131/#134/#135）逐项勾选标签清单，落笔前自检。
- **优先级决策路径显式化**：每条优先级判定必须给出 4 条判定路径（最低值、不升 high 两条、维持不变）。
- **可行性分支显式 A/B/C**：禁止仅给范围估算；每个子项内显式三档；补分支 D（分阶段）作为可选。
- **行号引用可溯源声明**：精确行号若无"已读取 main.py 验证"说明，必须前置声明"以下行号基于项目记忆与既有 PR 模式推断"。
- **新增/删除命令同步清单**：main.py + README + 帮助命令 + `_conf_schema.json` + CHANGELOG（+ `_GM_COMMAND_NAMES` 元组 + 跨适配器兼容文档）= 五/七处同步，硬性 checklist。
- **"默认行为"与"功能裁剪"**：UX 增强常被低估工作量，预留 40-80 行；功能裁剪即使 30 行删除也至少 0.5-1 天（七处同步独立工作量）。

## 6. 开发约定与注意事项

- 逻辑集中在 `main.py`，修改时全局搜索相似命令模式，避免遗漏。
- 管理员 QQ 号按字符串处理；群号统一 `str()` 归一化（缓存键/日志键/配置键一致）。
- QQ 操作处理接口失败、权限不足、消息超时、异常返回。
- 权限类改动覆盖：全局配置、群级覆盖、命令入口、权限判断函数、文档说明、回归测试。
- AstrBot API/命令解析兼容问题，区分插件启动/命令注册/命令调用/特定输入触发四个阶段。
- "API 返回 ok ≠ 实际生效"是已知反模式：设/取消头衔、设/取消管理、禁言、踢人、撤回、改群昵称、群待办、设精等命令均应检查 API 返回与状态，必要时回读。
- 跨私聊/群聊工作流须设计状态机、申请 ID、权限边界、持久化/过期、并发幂等、隐私、发送失败处理。
- 撤回类 PR 强制 9 项检查：时间窗（2 分钟）、限流、部分失败、自身消息排除、bot 消息处理、撤回目标过滤、缓存数据结构、OneBot 适配差异、配置 schema 一致性。删除类反向 9 项清单。
- OneBot 群待办类命令七处同步清单（owner-driven 命令新增）：main.py + README + 帮助命令 + `_conf_schema.json` + CHANGELOG + `_GM_COMMAND_NAMES` 元组注册 + 跨适配器兼容性文档。
- 验证清单：`python -m py_compile main.py` ≥ `ast.parse`；本地缓存回退类附最小单元测试；README/帮助/schema/CHANGELOG 同步；提交信息避免批量重复 `chore` commit。
- **对称命令扩展类 Issue**（#138/#139 沉淀）：必须显式对比 add/cancel 权限语义（添加通常宽于撤销）；七处同步清单扩展为针对"删除既有命令"的特别清单（含迁移指南 + 用户告知）。
- **owner-driven Issue 标签权重校准**：见 §4.22。
