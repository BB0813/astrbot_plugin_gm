# 项目概述：mjy1113451/astrbot_plugin_gm

> 累计反思 11 次

## 1. 项目简介

`astrbot_plugin_gm` 是用于 AstrBot 的 QQ 群管理插件，面向 QQ 群聊管理场景，提供插件管理员维护、禁言/解禁、踢人、撤回消息、群昵称、专属头衔、精华消息、群管理员设置等能力。

## 2. 技术栈与结构

- **语言**：Python 3.10+
- **框架**：AstrBot 插件体系
- **平台接口**：aiocqhttp / OneBot 相关 API
- **配置**：`_conf_schema.json` + `main.py` 运行时读取
- **许可证**：MIT

```text
astrbot_plugin_gm/
├── main.py              # 插件主逻辑：命令、权限、配置读取、OneBot API 兼容
├── metadata.yaml        # AstrBot 插件元信息
├── _conf_schema.json    # 配置 Schema / UI 暴露
├── README.md            # 安装、配置、命令和权限说明
├── docs/                # 补充文档
└── .sakura/             # 项目记忆、规则与反思
```

主要命令包括：`/设管`、`/取管`、`/禁言`、`/解禁`、`/禁我`、`/踢`、`/头衔`、`/取消头衔`、`/设管理`、`/取消管理`、`/设精`、`/设群昵称`、`/改昵称`、`/撤回`。

## 3. 权限与配置模型

1. **插件管理员**：来自 `plugin_admins` 或 `/设管` 动态维护；群主默认具备插件管理员身份。
2. **QQ 官方权限**：禁言、踢人、撤回、设管理、设精华、头衔等操作还依赖机器人在群内的官方权限及与目标成员的权限层级。
3. **专项权限与按群覆盖**：代码中可能存在 `title_admins`、`group_admin_admins`、`kick_admins`、`group_admins`、`group_overrides`、`get_group_setting` 及 `has_title_admin_rights`、`has_kick_admin_rights`、`has_group_admin_rights` 等机制。权限需求应优先检查这些入口，避免只改命令层。
4. **全局默认 + 群级覆盖**：多群场景需明确缺省回退、空列表/空对象、`0`、`None` 的语义。合法假值（如阈值 `0` 表示关闭）不能被误当成缺省并回退全局。

常见配置项：

- `show_recall_notice`：撤回后是否提示
- `reject_re_add`：踢人后是否拒绝重新加群
- `plugin_admins`：插件管理员 QQ 列表，建议按字符串处理
- `mute_kick_threshold`：禁言踢出阈值；若支持群级覆盖，应表述为“全局默认值”而非唯一配置来源

## 4. 近期反思沉淀

### 4.1 AstrBot 命令参数解析

Issue #106 反思表明：若命令签名使用 `count: int = 0/1`，AstrBot 可能在调用函数前按注解转换参数；框架解析阶段的错误无法被函数体内 `try/except int(count)` 捕获。

经验：

- 命令入口宜用 `str` 或可选原始参数接收，再在函数内解析、校验并返回友好提示。
- 同类问题需全局排查 `recall_cmd`、`recall_user_cmd` 以及所有 `: int =` / `count: int` 命令参数。
- 测试覆盖：无参、正整数、非法字符串、空字符串、负数、过大数字、中文数字、引用撤回、带 @ 和数量的撤回用户场景。
- 分析 Issue 时先确认错误阶段：启动、命令注册、命令调用，还是特定输入触发。若导致插件加载失败，优先级高于单命令异常。

### 4.2 `/撤回 N` 语义与消息筛选

Issue #109 反思集中在 `/撤回 1` 错误撤回指令本身：这应归类为 `bug`、优先级 `medium`，而不是因结构化输出失败降级为 `other`。

关键经验：

- `/撤回 1` 在群管语境中通常表示撤回“当前命令上方/之前的 1 条消息”，不应默认撤回命令自身。
- 修复应优先获取群历史并过滤当前命令 `message_id`，只撤回命令之前的 N 条可撤回消息。
- 引用撤回应保持优先级，不能被批量撤回逻辑破坏。
- 历史消息接口风险：不同 OneBot 实现可能不支持、返回顺序不同、字段结构不同、当前消息是否包含在历史中不一致、消息 ID 类型可能不同。
- 历史接口不可用时应明确提示，不宜回退成撤回指令自身并误报成功。
- 测试重点：`/撤回 1`、`/撤回 2/3`、不撤回命令自身、消息不足、权限不足、引用撤回、无参默认行为。

重复检测不能只看“撤回”两个字；要区分参数解析错误、撤回自身、权限不足、引用逻辑、撤回数量错误等不同问题。

### 4.3 `/取消头衔` 成功提示但未生效

Issue #111 反思表明：`/取消头衔` 返回成功但实际未清空群头衔，应归类为 `bug`、优先级 `medium`。分析链路应关注：

```text
/取消头衔 → unset_group_title_cmd → _clear_group_title
→ set_group_special_title → special_title="" / duration=-1 → 返回 ok 后提示成功
```

经验：

- 群管理 API “返回成功”不等于业务状态真实生效，尤其是头衔、设管理、禁言、踢人、改名片等操作。
- OneBot/NapCat/Lagrange/go-cqhttp 对 `special_title=""`、`duration=-1`、`duration=0`、不传 `duration` 的语义可能不同。
- 修复建议应区分命令逻辑问题、适配器兼容问题、权限问题和缓存延迟。
- 需要排查机器人是否有权限、目标是否为群主/更高权限、QQ 客户端是否缓存延迟、适配器是否吞掉权限错误。
- 可考虑调用 `get_group_member_info` 回读确认，但要说明回读可能受缓存/刷新时机影响，必要时给出“已发送请求，请稍后确认”或更谨慎提示。
- 固定检查链路：命令解析 → 权限判断 → API 参数 → 适配器兼容 → API 返回值 → 状态回读 → 用户提示。

### 4.4 按群专项权限与按群配置

Issue #105 反思集中在“头衔、管理、踢人等专项权限按群独立配置”：这类 Issue 更偏 `enhancement` / 配置权限增强，核心是从泛化插件管理员走向按动作授权，符合最小权限原则。

要点：

- 不能只新增配置项；要统一权限模型、命令入口、权限判断函数、配置 Schema、README、帮助文本、状态展示和测试。
- 若已有 `group_overrides` / `get_group_setting`，应复用并明确空列表、缺省、全局回退语义。
- 改动旧 `group_admins` 等配置语义时，要考虑迁移、废弃期或兼容读取，避免旧用户权限突然失效。
- 敏感操作（踢人、设管理、取消管理、头衔）必须做越权和误授权测试。

### 4.5 禁言踢出阈值的按群配置展示

Issue #107 反思表明：`mute_kick_threshold` 相关问题核心可能不是业务逻辑不支持按群读取，而是配置 UI/Schema/命令展示仍让用户以为只能全局设置。该类可归为 `bug` + `configuration/schema/ui/documentation`，优先级 `medium`。

关键经验：

- 按群配置要区分三层：业务读取层（是否走 `get_group_setting`）、命令管理层（是否能设置/查看/清除群级覆盖）、配置展示层（`_conf_schema.json`、AstrBot UI、README、插件配置命令是否表达清楚）。
- 顶层 `mute_kick_threshold` 存在不一定是 bug；它可作为全局默认值。问题在于是否标明“全局默认 + 群级覆盖”。
- 不宜简单删除全局项；更稳妥是保留全局默认、修改描述，并补群级覆盖示例。
- 状态展示最好显示“有效值 + 来源”，如当前群覆盖或全局默认。
- `0` 通常应表示关闭自动踢出，若群级显式配置为 `0`，不能回退全局。
- 需先确认用户说的“插件配置设置”是 AstrBot 控制台配置 UI，还是插件内部 `/配置` 命令；两者修复路径不同。

### 4.6 Issue 分析与标签经验

- 标题为“。”或信息极少时，不能依赖标题分类、重复检测或标题保留，应从正文和代码关键词重建问题。
- 对带 `[bug][medium]`、`[enhancement][medium]` 的标题可作为信号，但仍需结合正文和代码验证。
- 结构化输出某字段校验失败（如标题字段缺失）不应导致分类、标签、可行性整体丢失；应局部降级。
- 标签推荐优先匹配仓库实际标签；若未知，给通用主标签，并列可选标签，如 `command`、`group-management`、`configuration`、`schema`、`compatibility`、`needs-info`。
- “版本已更新，问题还存在”不必然是回归；除非确认旧版正常新版异常，否则谨慎标 `regression`。
- 重复检测应基于症状、触发路径和修复点，而不仅是同一命令或关键词。

## 5. 开发约定与注意事项

- 插件逻辑集中在 `main.py`，修改时应全局搜索相似命令模式，避免复制粘贴遗漏。
- 配置改动必须同步 `_conf_schema.json`、README、帮助/配置展示命令和示例。
- QQ 号建议按字符串处理，避免数字精度或格式问题。
- QQ 群管理操作依赖平台 API、机器人群权限和目标成员权限层级；必须处理接口失败、权限不足、异常返回和静默成功。
- 权限类改动覆盖：全局配置、按群配置、命令入口、权限判断函数、文档说明和回归测试。
- 对 AstrBot/API/命令解析兼容问题，应优先确认框架版本、插件版本/commit、OneBot 实现、完整堆栈和最小复现命令。
